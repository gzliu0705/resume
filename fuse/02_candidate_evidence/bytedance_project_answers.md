# ByteDance project evidence

## 1. 番茄 IP 热度模型看板

### 项目目的

- 服务于番茄头部 IP 影响力的持续监控与扩大。
- 监控 IP 热度指数的趋势变化，识别具有自传播迹象的高热度与高潜力 IP。
- 验证达人推书和市场宣发对 IP 影响力的提升效果，为后续宣发策略提供依据。
- 使用统一维度和数据口径，与其他出版方的头部 IP 横向比较，量化番茄 IP 的行业位置。
- 长期方向是与端内阅读及互动数据整合，形成全网热度指数并支持端内分发；该方向优先级较低，不应表述为已经完整落地。

### 负责内容与方法

- 建立网文 IP 热度评估指标体系，将消费、传播和搜索信号组织为三个核心维度。
- 整合内部数据和外部抓取平台数据，统一指标定义、统计粒度和更新时间口径。
- 建立自动化 ETL pipeline 汇总内部与外部平台数据；使用 PCA 生成客观统计权重，并通过跨部门共同确定的 AHP 权重纳入业务判断，拟合可横向比较、可按日跟踪的综合 IP 热度得分。
- 将综合评分流程部署至云端并搭建番茄 IP 热度业务看板，支持按 IP、出版方等维度进行横向比较，并按时间趋势进行纵向分析。

### 数据质量与自动化闭环

- 对外部抓取数据建立数据量、缺失、异常波动和更新状态监控，对指标异动进行上游追踪和口径归因。
- Bilibili：追踪视频日增 VV 的上游抓取与统计口径，修正长期不稳定、参考性较低的问题。
- Douyin：修正底层匹配逻辑并增加关键过滤条件，提高数据准确性和稳定性。
- Weibo：解决上游与下游数据粒度不一致的问题，统一可比口径。
- 传播和搜索模块：修正数据连接逻辑导致的缺失问题，提高指标完整性与数据利用率。
- Yunhe：协调业务更新逻辑与数仓更新逻辑，修复长期缺失、无法稳定参考的问题。
- 将多项人工更新流程迁移为线上自动化流程，并增加人工误填订正机制，减少人工维护和数据波动。
- 使用机器学习方法监测抓取平台的不稳定数据并进行预测填充，保障综合指数的连续性与参考价值。
- 自动化综合得分计算并加入上游数据异常监控，使异常发现、归因、口径订正和指数重算形成闭环。

### 业务使用与结果

- 看板按日监控 IP 热度变化，用于识别自然传播趋势、高热度 IP 和潜力 IP。
- 支持业务团队比较番茄与其他出版方头部 IP 的相对行业水平。
- 宣发活动后，业务团队使用看板观察趋势变化并评估达人推书和市场宣发效果。
- 随着数据口径持续订正和质量提升，看板成为 IP 宣发监控、推广建议和优先级判断的数据参考。
- 看板在内部目标用户中的 adoption 约为 60%。
- 对一个关键 IP，模型支持的资源投放策略相较此前投放策略实现了约 40% 的 download 提升。该结果应明确限定为关键 IP 的资源投放案例，不外推为所有 IP 或整体业务增长。

### 对外表述边界

- 用户已确认项目可命名为 `Fanqie IP Popularity Model & Dashboard`。
- 用户已确认可公开约 60% internal adoption，以及一个关键 IP 资源投放相较此前策略约 40% 的 download uplift。必须保留关键 IP 和 previous strategy 的比较边界。
- 不应把端内分发写成已落地结果；只能作为长期产品方向。
- 不逐项披露各外部平台的数据故障，简历中概括为 automated data-quality monitoring and anomaly attribution 即可。

## 2. 汽水音乐受众饱和度与拉新投放

### 项目目的

- 诊断汽水音乐新用户从激活到注册成功环节的转化下降。
- 区分内容互动表现较好但受众已高度渗透的创作者或垂类，与仍有真实增量用户空间的投放对象。
- 将用户分析转化为创作者和内容垂类的差异化投放决策。

### 负责内容与方法

- 通过跨产品用户 ID 关联，将抖音侧创作者受众与汽水音乐安装状态进行匹配，以创作者受众中已安装汽水音乐的用户占比衡量 audience saturation。
- 联合拉新量、激活到注册转化率和已安装用户占比，建立规则驱动的投放矩阵。
- 根据增量空间将创作者和内容垂类划分为饱和、发展中和高潜力层级，为常规投放与增量投放提供选择依据。

### 业务落地与结果

- 分层结论被市场团队实际采用。
- 对受众已趋于饱和的常规投放垂类显著减少投放，避免继续将资源投入缺少增量空间的人群。
- 当前没有确认可公开的注册转化 uplift、CAC、ROI 或新增用户量，因此简历只陈述已落地的投放调整，不虚构量化收益。

### 对外表述边界

- 新用户转化必须准确表述为 activation-to-registration conversion，而不是曝光到下载或下载到激活。
- 分层方法是 rule-based targeting matrix，不应包装为 clustering 或机器学习模型。
- 可以说明 cross-product audience saturation 或 existing-user penetration；若涉及隐私或合规审查，则不展开底层用户 ID 匹配细节。
- 项目适合定位为 incremental-user targeting and resource allocation，而不是泛化的 user segmentation。
