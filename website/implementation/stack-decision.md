# Stack Decision

## Purpose
Record the implementation approach after copy and wireframes stabilize.

## Decision Rule
Do not finalize the tech stack before:
- homepage structure is stable
- core copy is drafted
- Path & Traces interaction is wireframed

## Options to Evaluate

### Option A — Framer
Best if:
- elegant editorial layout is enough
- motion remains light
- custom synchronized interactions are limited
- speed to publish matters most

### Option B — Custom-coded site
Best if:
- Path & Traces requires richer synchronized behavior
- cat-based interaction needs more control
- custom page structure and future extensibility matter more

## Evaluation Criteria
- layout flexibility
- scroll interaction control
- ease of iteration
- maintenance cost
- responsiveness
- speed to launch
